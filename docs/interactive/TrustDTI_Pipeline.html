The ChEMBL ↔ BindingDB overlap problem

Both databases import from each other. Counting shared drug–protein pairs naively looks impressive — until you exclude the records each database copied from the other.

Naive — every record vs. every record
872,761 shared pairs
Independent records only — the honest number
66,145 shared pairs
The naive count is ≈13× inflated. 52% of BindingDB's human records are curated straight from ChEMBL; ChEMBL in turn imports 2.2M rows of BindingDB's own patent data (source ID 37). Decision: build the first network on ChEMBL alone; BindingDB's independent patent pairs (~426k, mostly newer than this ChEMBL release) get reconsidered for the time-based test later.

A data source can quietly distort your conclusions

Median measured potency (pChEMBL — higher means a stronger drug), with and without PubChem's high-throughput screening data. Five protein families shift by more than a full order of magnitude.

● all sources   ● excluding PubChem screens  ·  a per-family activity threshold has to control for this or it will encode screening artefacts as biology.

05 How we know Stage 1 can be trusted

Verification, not vibes

✓

Checksum-verified

ChEMBL's SHA-256 matched the publisher's own checksums.txt exactly: 33c2037…290d281. BindingDB's MD5 matched too.

✓

Row-count verified

COUNT(*) FROM activities on the local database returned 24,527,044 — identical to ChEMBL's own published release notes.

✓

Reproducibility-verified

Deleted every output, re-ran extraction and profiling from the raw database from scratch. All 16 result files came back byte-for-byte identical.

✓

Automated tests

9 fast tests run in ~2 seconds on every change; a 10th, full-database test (~1 hour) runs before any data-version change.

✓

Cross-source agreement

On 40,988 potency values measured independently by both databases: median difference 0.0 log units; 95.6% agree within 1 log unit.

✓

Ground-truth spot check

A specific real row — imatinib vs. FLT3, IC50 > 30,000 nM — was confirmed identically via the ChEMBL web API and a direct SQL query.
