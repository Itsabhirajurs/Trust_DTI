Two data rules that protect the whole project

Both prevent silent errors that would make a drug–protein model look better (or worse) than it really is.

Rule 1: every drug–protein pair has exactly one of three states

ACTIVE

A measurement exists and shows meaningful activity (threshold set from real data in week 2 of the project plan).

INACTIVE

A measurement exists and shows no meaningful activity under the tested conditions, e.g. "not active", IC50 > 10 µM.

UNTESTED

No measurement, or an unusable one ("inconclusive", "not determined"). Never converted to INACTIVE: most drug–protein pairs were simply never tested.

Rule 2: censored values are not exact values

Real row, ChEMBL activity 884645: imatinib vs FLT3, IC50 > 30,000 nM.
It means "no activity found up to 30 µM" (a lower bound), not "potency = 30 µM".

What this means for the pipeline

  • Keep every relation: = > < >= <= >> <<
  • Never filter on pchembl_value IS NOT NULL
  • "inconclusive" (1.73M rows) is UNTESTED, not INACTIVE
  • Enforced by automated tests (tests/test_chembl_extract_data.py)
  • Stated openly as a positive-unlabelled problem if negatives turn out scarce
